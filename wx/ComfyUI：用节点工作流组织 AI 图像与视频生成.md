ComfyUI 是一个用节点图组织 AI 生成任务的开源工具。你可以把模型加载、提示词编码、采样、图像解码等步骤连接起来，保存成工作流，再用于后续创作或程序调用。它的用途已经覆盖图像、视频、音频和 3D；对于初次接触的人，基础文生图仍然是理解它最直接的入口。

**当你需要反复调整生成过程、复用一套处理步骤，或者把生成能力接入自己的应用时，ComfyUI 值得学习。** 如果只是偶尔输入一句描述、取一张图片，节点图带来的学习成本也需要考虑。

本文依据 [ComfyUI 官方仓库](https://github.com/Comfy-Org/ComfyUI)的 README 和 API 示例整理，侧重解释它如何工作，以及开始使用前需要准备什么。

## 先分清模型、节点和工作流

第一次打开 ComfyUI，最显眼的是画布上的方框和连线。理解它们之前，先把三个概念分开。

模型是执行生成或理解任务的权重文件，例如 Stable Diffusion、FLUX 或视频生成模型。ComfyUI 负责加载和调用这些模型，本身并不等于某一个生成模型。

节点是一个处理步骤。它可能读取模型，也可能把文字编码成条件、执行采样，或保存图片。节点之间的连线传递有类型的数据：模型对象、条件、潜空间数据、图像等。能否连接取决于接口要求，不能只凭方框的位置判断。

工作流则保存节点、参数和连接关系。同样的模型，搭配不同的工作流，可以用于文生图、图生图、局部重绘或放大。换成另一类模型时，往往还要更换加载器、文本编码器或采样相关节点；修改模型文件名未必足够。

## 一张图片怎样经过这些节点生成

官方基础 API 示例使用经典的 Stable Diffusion 文生图结构。它可以概括为下面这条数据流：

```text
Checkpoint 加载器 ── MODEL ───────────────────┐
                 ├─ CLIP → 正／负提示词编码 ──┤
                 └─ VAE ─────────────────┐   │
空潜空间图像 ────────────────────────────┼─→ KSampler
                                         │   ↓ 潜空间结果
                                         └─→ VAE 解码 → 保存图像
```

这是一张示意图，实际连线以节点端口为准。各步骤的作用如下：

| 步骤 | 主要作用 | 常见调整项 |
| --- | --- | --- |
| Checkpoint 加载器 | 在这个基础流程中，提供生成模型、CLIP 和 VAE | checkpoint 文件 |
| 提示词编码 | 将正向和负向文字转成采样需要的条件 | 描述内容、负向提示词 |
| 空潜空间图像 | 指定文生图所需的潜空间尺寸和批量 | 宽度、高度、批量大小 |
| KSampler | 按模型、条件和采样设置执行去噪生成 | seed、steps、CFG、采样器、调度器 |
| VAE 解码 | 把潜空间结果转换成像素图像 | 匹配的 VAE |
| 保存图像 | 将结果写入文件 | 文件名前缀 |

这里最容易混淆的是潜空间数据。KSampler 输出的结果仍然需要经过 VAE 解码，才能得到后续保存节点使用的图像。文生图时，空潜空间节点负责尺寸等设置，采样过程再根据 seed 等参数构造所需噪声。

这些节点名称对应官方的基础示例。其他模型可能采用独立的模型加载器和文本编码器，也可能有不同的条件结构。入门时先看懂一条完整的数据流，比背下所有节点名称更有用。

## 节点图为什么值得保存

假设你正在做一组商品场景图：先生成主体，再调整局部，最后放大输出。如果每次都重新操作，流程很容易发生细微变化。保存工作流后，可以保留这套处理关系，只替换输入图片或提示词。

ComfyUI 支持将工作流保存为 JSON，也能从保留相关元数据的生成图片中恢复工作流。官方 README 提到，把生成的 PNG 拖入界面，可以载入其中保存的工作流和 seed。经过截图、压缩平台或图片处理软件后，元数据可能丢失，因此分享流程时最好同时提供 JSON。

工作流文件通常不包含模型权重，也不会把第三方节点的运行环境一起打包。别人给你一个 JSON，可能还需要补齐模型、安装对应节点，并解决版本兼容问题。

如果希望以后重新运行，建议随工作流记录：

- ComfyUI 版本和自定义节点版本。
- 模型的名称、来源及文件哈希；有输入素材时，也保存素材。
- seed、采样参数，以及会影响结果的运行设置。
- 一张参考输出，方便判断恢复后的结果是否符合预期。

这些记录有助于复现过程，但跨硬件、计算后端或软件版本，仍可能出现数值差异。固定 seed 不能单独保证逐像素一致。

## 执行效率来自哪里，又受什么限制

README 说明，ComfyUI 会执行具有有效输入、并通向输出的相关图部分；连续运行时，也会根据变化重新执行受影响的部分。例如只修改末端的图像处理步骤，上游计算在缓存可用时可以复用。

实际收益取决于修改发生在哪里。更换主模型或改变提示词，通常会影响后续生成；随机参数、节点实现和缓存设置也会改变复用情况。画布上有多少节点，不能直接用来判断一次任务需要多少时间。

显存管理同样不能只看“能否启动”。模型规模、分辨率、批量大小，以及视频的帧数都会影响资源需求。模型卸载、量化或权重流式传输可以让部分任务适应较小显存，但还可能增加内存占用和数据传输开销。官方 README 的低显存能力描述，应结合具体模型与工作流验证，不能当作所有任务的统一配置要求。

## 初次安装，先选一条适合自己的路径

官方提供桌面应用、Windows 便携包、手动安装和 Comfy Cloud。选择时，可以先看自己是否需要管理底层环境。

| 方式 | 更适合的情况 | 开始前要确认的事 |
| --- | --- | --- |
| 桌面应用 | 希望减少安装步骤的 Windows、macOS 用户 | 当前支持的系统与硬件 |
| Windows 便携包 | 希望使用相对独立的运行环境 | 下载包是否匹配显卡和驱动 |
| 手动安装 | Linux 用户，或需要控制依赖与后端的用户 | Python、PyTorch、计算后端的兼容性 |
| Comfy Cloud | 希望使用官方托管服务 | 费用、资源限制与数据处理安排 |

对新用户，README 优先推荐桌面应用。手动安装需要按硬件选择依赖，不宜照抄一条面向 NVIDIA 的命令用于所有设备；具体步骤应以[仓库安装说明](https://github.com/Comfy-Org/ComfyUI#installing)为准。

安装完成后，还需要准备工作流要求的模型。有些基础 checkpoint 放在 `models/checkpoints`，VAE 放在 `models/vae`；另一些模型需要多个独立文件和不同目录。下载时按照对应模板的说明放置，避免仅凭扩展名判断。

本地模型与依赖准备完成后，核心工作流可以离线运行。工作流若使用调用外部服务的 Partner/API 节点，则会涉及联网、凭据和可能的费用。官方 Cloud、本地推理和这些外部节点是不同的运行方式，使用前应看清具体流程。

## 第一次运行，只做一个小实验

建议先从[官方工作流模板](https://comfy.org/workflows)或[示例页面](https://comfyanonymous.github.io/ComfyUI_examples/)中，挑一个与本机资源相符的基础文生图流程。先用内置节点运行成功，再逐步增加功能。

1. 对照模板补齐模型，确认节点中能选到正确文件。
2. 使用较小分辨率和单张输出，完成第一次生成，保存工作流与图片。
3. 固定 seed，每次只改一个参数，例如提示词或采样步数，观察变化。
4. 需要局部修改、结构控制或放大时，再添加相应节点。

如果出现缺失节点，先确认节点来自哪个扩展；如果出现模型不兼容，先检查加载器和模型系列是否匹配。自定义节点包含可执行代码，也会引入额外依赖，应从可确认的来源安装，并记录版本。

## 工作流如何接入自己的应用

ComfyUI 的官方示例展示了本地 HTTP API 和 WebSocket 的使用方式。一个常见调用过程是：先在界面中调通工作流，导出 API 格式，再由程序替换提示词、seed 或输入文件等参数并提交执行。

这里有两种文件用途需要分清：编辑器工作流 JSON 保存画布信息；API 格式 JSON 面向后端执行，主要描述节点类型、输入和连接。接口调用时应使用界面导出的 API 格式。

根据官方示例，基本的集成路径是：

1. 向本地服务的 `POST /prompt` 提交执行图。
2. 使用 WebSocket 监听任务执行状态。
3. 根据任务标识读取 `/history/{prompt_id}`，找到输出信息。
4. 通过 `/view` 获取生成的图像文件。

收到提交响应表示任务已被接收，生成完成仍需检查后续状态。若要把它做成多人使用的产品，还需要应用层处理身份认证、任务隔离、失败重试和资源限制。这些属于集成设计，不能由单个 API 示例代替。

项目仓库采用 GPL v3 许可证。模型权重、自定义节点和外部服务各有自己的许可或条款，使用与分发时需要分别核对。

## 什么时候适合投入时间学习

需要反复试验生成参数、处理固定步骤，或者把一套生成流程交给程序调用的人，更容易用上 ComfyUI 的工作流能力。代价是需要理解模型组件、数据类型和依赖关系。

开始时可以给自己定一个具体目标：保存一条能运行的基础流程，隔天重新打开它，换一段提示词再生成一次。做到这一步后，再决定下一步是加入图像编辑、学习视频模型，还是尝试 API 集成。
