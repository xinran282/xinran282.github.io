# 如何证明新的 Prompt 比旧版更好

判断一个新 Prompt 是否优于旧版，不能只靠“读起来更舒服”或者“感觉回答更像人话”。这种判断太容易受个人偏好影响，也很难复现。更稳妥的做法，是把 Prompt 放到固定样本、固定指标和盲评流程里比较。

真正有说服力的结论，通常来自四类证据：同题对比、人工盲评、回归测试、成本指标。四者一起看，才算站得住。

## 先定义“更好”是什么意思

在比较之前，先把目标说清楚。不同任务的“更好”根本不是一回事：

- 写作类任务，可能看表达是否顺、结构是否稳、事实是否少出错。
- 代码类任务，可能看可执行率、错误率、修改次数。
- 问答类任务，可能看准确性、覆盖率、是否遵守格式。
- 工具调用类任务，还要看是否按步骤调用、是否少走弯路。

如果目标没定清，最后就只能讨论“我更喜欢哪一版”，而不是“哪一版更强”。

## 用同一批题目做 A/B 对比

最基础的方法，是准备一组固定样本，让旧 Prompt 和新 Prompt 跑同一批输入。

样本最好覆盖三类内容：

1. 常规样本：最常见的真实请求。
2. 边界样本：容易出错、容易跑偏、容易格式崩掉的请求。
3. 压力样本：长输入、多约束、冲突要求、信息不完整的请求。

这样做的目的很简单：新 Prompt 不能只在顺手的题上赢，也要能扛住难题。

## 做盲评，不要先看版本号

人是会被标签影响判断的。只要评审知道哪个是新 Prompt，结论就很容易偏。

所以更靠谱的办法，是把输出匿名化，让评审只看结果，不看来源。然后按统一标准打分，例如：

- 是否答对
- 是否完整
- 是否遵守格式
- 是否有明显幻觉
- 是否比旧版更简洁

如果可能，最好让两位以上评审独立打分，再看一致性。这样比单人拍脑袋更稳。

## 不只看平均分，还要看失败率

新 Prompt 的平均分高，不代表它一定更好。它可能只是“多数时候更好，但一旦翻车就翻得更狠”。

所以要同时看：

- 平均分
- 通过率
- 重大错误率
- 最差样本表现

如果新 Prompt 只是在简单题上更流畅，但在边界题上更容易胡说，那它未必值得替换。

## 回归测试是底线

每次改 Prompt，都要防止旧能力被悄悄弄坏。这个过程和软件测试很像。

你可以维护一组回归样本，里面放这些内容：

- 旧版已经做对的典型题
- 历史上翻过车的题
- 业务里不能再错的题

新 Prompt 上线前，必须先跑这批样本。只要核心场景退步，就不能只看“新答案更会说话”，而要认真处理。

## 还要看成本和延迟

Prompt 更好，不一定只是回答更好，也可能是：

- 更短
- 更稳
- 更少调用工具
- 更少轮次
- 更低 token 成本

如果新 Prompt 提升了 3 分准确率，却让 token 翻倍、响应变慢、工具调用更多，那它未必是更好的工程选择。

所以比较时，别只看质量，也看成本。

## 一个更完整的判定方式

比较实用的做法，是把结论拆成三层：

1. 质量层：答案对不对，完整不完整。
2. 稳定层：换一批样本后还稳不稳。
3. 工程层：成本、延迟、维护复杂度有没有变差。

只有三层都过关，才能说新 Prompt 更好。

## 一个简单的评估流程

可以直接按这个顺序做：

1. 定义目标和评分标准。
2. 准备固定样本集。
3. 跑旧 Prompt 和新 Prompt。
4. 匿名化输出，做盲评。
5. 看平均分、通过率、失败样本。
6. 重点检查回归项和成本。
7. 再决定是否替换。

这个流程不花哨，但它能把“感觉”变成“证据”。

## 最后一句话

要证明新 Prompt 比旧版更好，关键不是把它写得更像宣传文案，而是让它在同一批题目上，经得起盲评、回归和成本三重检验。能稳定赢，才算真的赢。

## 怎么把回归做成半自动

回归测试不该每次都全靠人看。更现实的做法，是先让机器做第一轮筛选，再把少量难例交给人。

可以按三层来做：

- 机器先筛：先查格式、关键字段、长度、规则违规、明显失败。
- 自动打分：有标准答案的用 exact match、F1 或结构比对；没有标准答案的，用 pairwise judge 或 LLM judge 先做初判。
- 人工复核：只看机器判断不稳的边界样本、风险最高的样本，或者抽样校准。

这样一来，人工不再负责全量审核，而是负责裁决和校准。真正耗人力的部分会被压到很小。

如果线上系统已经足够稳定，还可以再加一层灰度验证，只让小比例流量走新 Prompt，继续观察失败模式和回归项。
