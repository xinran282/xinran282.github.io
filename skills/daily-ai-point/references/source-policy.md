# 来源与时效策略

## 可接受的来源

每日知识点不要求来源都是论文。按主题选择最接近事实源头的材料：

- **研究与算法**：原始论文、作者主页、实验室技术报告和官方实现。
- **模型与产品**：模型发布公告、官方技术报告、模型卡、API 文档、版本说明和定价/能力变更公告。
- **AI Skill 与工具**：Skill 的官方说明、规范、示例仓库、变更日志，以及维护者对行为边界的说明。
- **工程实践**：官方仓库 issue/README、维护者博客、基准报告和可复现实验。
- **观点与解读**：有署名、能链接原始材料并区分事实与判断的技术博客、播客文字稿或专家文章。

## 来源分级

- **Tier 1（首选）**：官方文档、官方 release notes、模型发布页/模型卡、原始论文、作者或组织的官方仓库、官方 Skill 规范。
- **Tier 2（可用）**：知名实验室或维护者博客、同行评审论文的可靠解读、可复现实验报告、带明确出处的专家分析。
- **Tier 3（线索）**：媒体、论坛、社交平台和无出处的社区内容，仅用于发现候选，不作为关键事实的唯一依据。

每篇 `new` 或 `current` 知识点至少引用一个 Tier 1 来源。若主题本身是观点、经验或 Skill 用法，可以用 Tier 2 作为主来源，但必须明确标注“观点/二手解读”，并降低 `source_quality`。

## 研究与核验要求

1. 先按“主题 + docs/release notes/paper/blog/skill/benchmark”等关键词寻找材料，再打开原始页面核对。
2. 对模型、API、Skill 和工具记录发布日期、版本号、访问日期（必要时），不要把没有日期的内容称为“最新”。
3. 把“来源报告的事实”和“作者的推断/观点”分开写；博客观点不能扩写成行业共识。
4. 对 benchmark 记录任务、模型版本、数据集和指标；对观点文章说明其适用场景和不确定性。
5. 来源互相矛盾时保留分歧并列出双方链接，不给出无依据的确定结论。
6. 只有 URL 可访问且为 HTTP(S) 时才写入历史库；不伪造链接，也不引用模型记忆中的 URL。
