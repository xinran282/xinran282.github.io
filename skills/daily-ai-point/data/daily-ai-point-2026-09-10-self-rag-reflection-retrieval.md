# 今日知识点：Self-RAG：让模型自己判断何时检索、何时反思

> 一句话：Self-RAG 把“要不要查资料、证据够不够、答案是否可靠”变成模型可学习的决策。

**分类**：检索与知识　**难度**：4　**资料截至**：2026-09-10

## 它解决什么问题

普通 RAG 往往对每个问题都先检索固定数量的文档，再要求模型生成答案。这样做有两个相反风险：简单问题被无关资料干扰；复杂问题检索到的证据不足，模型仍可能把猜测写成事实。更关键的是，系统通常只在最终答案阶段评估质量，无法知道错误来自“不该检索”“检索不准”还是“没有忠实使用证据”。

Self-RAG（Self-Reflective Retrieval-Augmented Generation）把检索和反思纳入生成过程。模型学习在需要时发出检索请求，并对检索结果和自身输出进行批评，从而按问题难度自适应地使用外部证据。

## 工作机制

Self-RAG 在普通文本 token 之外引入反思 token（reflection tokens），用来表达控制信号，例如：

- **Retrieve**：是否需要检索，以及何时检索；
- **ISREL**：检索到的段落是否与问题相关；
- **ISSUP**：生成的回答是否被证据支持；
- **ISUSE**：回答是否有用、是否真正解决问题。

训练数据包含问题、检索段落、生成答案和这些反思标签。模型先生成检索决策；若选择检索，系统返回候选段落，模型再生成答案和对应评价。训练目标既包括语言建模损失，也包括对反思 token 的学习，使模型能把“查资料”和“评估资料”作为生成轨迹的一部分。

推理时可以设置不同策略：只保留被判定相关且支持度高的答案；让模型比较多个候选；或在证据不足时继续检索。与固定 RAG 相比，Self-RAG 的核心变化不是换一个向量库，而是让模型参与控制检索循环。

## 一个具体例子

问题：“某 API 在 2025 年后的版本是否支持流式工具调用？”这是一个强时效、强版本问题，Self-RAG 可能先输出 Retrieve 信号，检索官方版本文档，再判断段落是否相关。若文档只说明“工具调用”却没有“流式”或版本号，ISREL 可能不够，模型应继续检索或明确说证据不足，而不是根据旧知识补全。

相反，问题“2+2 等于多少”不需要外部资料，模型可以跳过检索，减少延迟和被噪声干扰的机会。实际系统仍需把高风险动作（改数据、发邮件）交给独立权限层，不能只依赖模型生成的反思 token。

## 它和什么容易混淆

Self-RAG 不等于在提示词末尾加一句“请自我反思”。它通过训练让模型产生可识别的检索与评价信号，并把信号接入控制流程。它也不同于 Query2doc：Query2doc 主要在检索前生成伪文档扩展查询；Self-RAG 关注的是检索时机、证据相关性和生成后的支持度，二者可以组合，但学习目标不同。

## 局限与实践建议

反思标签本身需要可靠标注或评审模型，错误标签会让模型学会形式化地“说自己有证据”。多轮检索增加延迟和 token 成本；若召回器质量差，模型再会反思也无法凭空得到缺失事实。评估时应分别记录检索触发率、相关段落比例、引用支持度、答案正确率、平均检索轮数和 P95 延迟。对日期、版本、法律和医疗问题，要优先限定权威来源，并在证据不足时允许拒答。

## 为什么现在值得关注

Self-RAG 论文发表于 2023-10-17。随着 RAG 从“固定流水线”走向 Agent 式工作流，何时检索、何时停止和如何验证证据成为系统质量的关键控制点。该方法提供了一个清晰的研究框架，但具体实现和模型能力会随训练数据、检索器及部署策略变化。
