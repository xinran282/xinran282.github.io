# 今日知识点：权重量化：用低比特参数降低大模型推理成本

> 一句话：把训练好的 FP16 权重压成 INT4 等低比特表示，少占显存并减轻内存带宽压力。

**分类**：推理与效率　**难度**：3　**资料截至**：2026-09-13

## 它解决什么问题？

推理时常先遇到显存上限。约 70 亿参数的模型用 FP16 存权重约需 14 GB，还要留出 KV cache 和激活。权重量化（W-only PTQ）在训练后压缩参数，使更大模型能放入同一张卡。

## 工作机制

量化把连续权重映射到有限整数：`q = round(w / s)`，还原时 `ŵ = s·q`。`s` 按通道或每组（如 128 个权重）保存，减少异常值影响；内核读取整数并即时反量化。

训练后量化不能只做四舍五入。GPTQ 用少量校准样本，以 Hessian 近似二阶误差，决定量化顺序并补偿误差；AWQ 先观察激活分布，保护被激活放大的少数显著通道，再压缩其余权重。两者都在“压缩率”和“层输出变化”之间做取舍。

## 一个具体例子

7B 模型从 16 bit 改为 4 bit，理想权重存储约由 14 GB 降至 3.5 GB（4/16），scale 等元数据会增加少量开销。部署需选择匹配的 INT4 kernel；若代码或长上下文退化，应比较 4/8 bit 和不同 group size 的验证集。

## 容易混淆的概念

- **剪枝**删除连接并改变稀疏结构；量化保留连接，只改变数值精度。
- **量化感知训练（QAT）**在训练中模拟量化并更新权重，通常更准但成本更高；GPTQ/AWQ 是训练后的校准方法。
- **激活量化**还压缩中间激活，节省更多带宽，却更受输入分布和异常值影响；W-only 更容易先落地。

## 局限与实践建议

误差在数学/代码、超长上下文和少见语言上可能被放大。校准数据要覆盖真实请求；不同 kernel 对分组大小和权重布局有要求，能加载不代表更快。上线前比较任务准确率、首 token/每 token 延迟和峰值显存，并保留 FP16 回退。

## 为什么现在值得关注

GPTQ（2022-10-31）和 AWQ（2023-06-01）分别代表二阶误差补偿、激活感知保护两条路线。它们把“模型大小—质量—速度”的取舍变成比特数、分组大小、校准集和 kernel 的可测参数；掌握这套方法，比记住某个模型的 4 bit 文件更能迁移到新模型。
