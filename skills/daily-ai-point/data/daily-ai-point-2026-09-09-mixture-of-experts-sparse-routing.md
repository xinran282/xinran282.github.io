# 今日知识点：稀疏混合专家路由：为什么模型容量可以增长得比计算量更快

> 一句话：每个 token 只激活少数“专家”子网络，让模型拥有更大参数容量而保持近似固定的单次计算量。

**分类**：基础原理　**难度**：4　**资料截至**：2026-09-09

## 它解决什么问题

把 Transformer 做大通常能提升表达能力，但如果每个 token 都经过全部参数，计算和显存带宽会随模型规模一起增长。混合专家（Mixture of Experts，MoE）把某些密集前馈层替换成多个专家网络，并让路由器针对每个 token 选择其中少数几个。这样模型的**总参数量**可以很大，单个 token 的**激活参数量**却相对较小。

## 工作机制

一个 MoE 层包含 N 个结构相同或相近的专家 \(f_1,\ldots,f_N\)，以及路由器 \(g(x)=\operatorname{softmax}(W_rx)\)。对输入 token 表示 x，路由器产生 N 个分数，选择 top-k 个专家：

\[
y=\sum_{i\in\operatorname{TopK}(g(x))}\tilde g_i(x)f_i(x)
\]

其中 \(\tilde g_i\) 是被选专家分数的归一化权重。训练时，token 会被分发到对应专家所在设备，计算完成后再按原顺序合并。为了防止所有 token 都挤到同一个专家，通常加入负载均衡辅助损失；同时为每个专家设置 capacity，超出的 token 可能被丢弃、转为残差路径或重新路由。

Switch Transformer 将 top-1 路由作为简化方案：每个 token 只去一个专家，通信和实现更简单；top-2 等方案允许两个专家共同处理，表达更灵活但计算和通信更高。路由策略不是免费扩容，它会把训练难点从“算不动”转移到“如何稳定分配 token”。

## 一个具体例子

假设有 16 个专家，每个 token 选择 top-2。总参数容量约等于 16 个前馈网络，但每个 token 只执行 2 个专家，理论激活比例约为 2/16（还要加共享的注意力层和路由开销）。一批 token 中，路由器可能把代码相关 token 更多地送入某些专家，把自然语言描述送入另一些专家；这些“专业化”不一定由人工标签指定，而是训练中逐渐形成。

在多 GPU 服务中，token 还要跨卡发送到目标专家，再把结果发回原卡。若 batch 太小或专家分布不均，通信和等待时间会抵消稀疏计算收益，因此应同时观察专家负载、丢 token 比例和跨设备通信量。

## 它和什么容易混淆

MoE 的“稀疏”指每个 token 只激活部分参数，不等于把权重矩阵做稀疏化，也不等于剪枝。剪枝是永久删除或置零参数；MoE 则保留多个专家并按输入动态选择。MoE 也不等同于多模型投票：专家通常共同属于一个端到端训练的模型，路由器负责按 token 粒度分配，而不是独立模型各自生成完整答案。

## 局限与实践建议

路由器可能出现负载塌缩：少数专家过载、其他专家闲置，导致容量溢出和训练不稳定。辅助均衡损失过强又可能破坏有意义的专家分工。工程上要记录每层专家的 token 分布、capacity factor、丢弃率、跨卡通信和端到端延迟。推理时总参数很大仍会占用存储，量化和专家并行策略需要一起设计；“激活参数少”不代表显存、网络带宽或部署成本一定低。

## 为什么现在值得关注

Switch Transformer 论文发表于 2021-01-08。MoE 已成为扩大模型容量的一条重要路线，但其实际收益取决于路由均衡、并行通信和服务负载。理解总参数与激活参数的区别，有助于正确解读模型规模、推理成本和 benchmark 声称。
