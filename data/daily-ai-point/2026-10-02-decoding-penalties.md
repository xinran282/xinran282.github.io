# 今日知识点：频率惩罚与存在惩罚：解码参数如何影响生成

> 一句话：在采样 logits 上按历史 token 惩罚，减少重复并鼓励新词。

**分类**：基础原理　**难度**：3　**资料截至**：2026-10-01

## 它解决什么问题

温度、top-p、top-k 控制随机性，但不直接回答“为什么模型总说同一句话”。频率惩罚（frequency penalty）和存在惩罚（presence penalty）针对的是**已出现 token 的影响**：前者按已出现次数持续降低重复 token 的 logits，后者只看 token 是否出现过，不累计次数。它们常用于开放式生成，让回答少重复、多引入新内容；但在事实问答、代码、数学和翻译中可能伤害准确性。

## 工作机制

### 频率惩罚：按次数累计

若 token t 已出现 count(t) 次，常见实现为：

logit'(t) = logit(t) − α × count(t)

α 通常在 0–2。次数越多，惩罚越强。因此高频停用词和重复短语会被持续压低。

### 存在惩罚：按是否出现过

若 token t 已出现过至少一次：

logit'(t) = logit(t) − β

与出现次数无关。一个 token 出现 1 次和 100 次受到同样惩罚，因此它更倾向“引入没出现过的词”，而不是完全禁止重复。

### 与温度/top-p 的区别

温度缩放整个分布的尖锐程度；top-p/top-k 截断候选集合；频率/存在惩罚是在采样前对特定 logits 的加性调整。它们可以组合使用，但组合效果需实测。

## 一个具体例子

假设某步候选 logits 为：
- A：5.0，已出现 4 次；
- B：4.8，未出现；
- C：4.5，已出现 1 次。

若频率惩罚 α=0.2：
- A：5.0 − 0.2×4 = 4.2
- B：4.8 − 0 = 4.8
- C：4.5 − 0.2×1 = 4.3

B 从第二位升至第一位。数字仅示意；真实词表和上下文更复杂。若换存在惩罚 β=0.5：
- A：5.0 − 0.5 = 4.5
- B：4.8
- C：4.5 − 0.5 = 4.0

A 与 C 的差距被缩小，但 A 的高次数不再额外加重惩罚。

## 它和什么容易混淆

- **重复惩罚（repetition penalty）**：一些开源实现用除法/乘法形式惩罚已出现 token，与 frequency penalty 的累计线性形式不同；
- **温度**：温度改变整体随机性，不区分 token 是否出现过；
- **top-p / top-k**：它们修剪候选集，不改变候选相对 logits；
- **对比解码**：对比解码用另一模型的分布系统性扣除常见偏差，不是按单个序列历史计数。

## 局限与实践建议

- 事实与代码任务慎用：关键标识符、数字、专业术语天然需要重复；
- 惩罚过强会导致生僻词、断句或不自然表达；
- 参数跨模型、任务、语言不稳定，不能盲目照抄；
- 与 temperature/top-p 组合时需做小规模评测；
- API 的具体定义和取值范围以当前文档为准，不同框架实现并不等价。

## 为什么现在值得关注

这些参数仍出现在主流文本生成 API 中，是控制开放式输出重复的直接手段。理解“按次数累计”和“按是否出现”的差别，能避免把减少重复误当成提升正确率。
