# 今日知识点：LoRA 的显存机制：为什么冻结权重也能省显存

> 一句话：冻结大矩阵训练低秩增量，训练态显存随可训练参数而非总参数增长。

**分类**：训练与对齐　**难度**：4　**资料截至**：2021-06-17

## 它解决什么问题

LoRA 已讲过“低秩增量 W₀+BA”。这次聚焦训练时的显存账本：为什么总参数 65B 的模型，插入 r=8 的低秩模块后，可以在单张消费级 GPU 上训练？关键不是“权重变小”，而是**训练态显存主要由可训练参数的梯度和优化器状态决定**。冻结参数只需保留前向计算所需权重，不需要为反向传播和优化器长期保存完整训练状态。

## 工作机制

### 训练态显存从哪里来

对每个可训练 FP16 参数：
- 权重：2 字节；
- 梯度：约 2 字节；
- Adam 状态：一阶矩 + 二阶矩，混合精度下通常约 8 字节。

合计约 12 字节/参数，还没计入激活、临时 buffer 与 kernel 工作区。冻结参数不需要梯度与 Adam 状态，只需保留参与前向/反向路径计算的权重。

### LoRA 改变了什么

LoRA 冻结 W₀，只训练 A∈R^{r×k} 和 B∈R^{d×r}。因此训练态显存大幅下降，并可按需合并：
- 训练后 W₀+BA 可合并成等效权重，推理结构与原模型一致；
- 服务时也可不合并，直接热插拔不同 LoRA 适配器。

## 一个具体例子

考虑 4096×4096 的权重矩阵：
- 全量微调该矩阵：约 16.8M 参数。仅训练态约 16.8M×12B ≈ 201MB；
- r=8 LoRA：A+B 共 (4096+4096)×8 ≈ 65.5K 参数，训练态约 786KB。

两者相差约 256 倍（忽略激活与临时空间）。数字来自矩阵尺寸推导，仅用说明机制。LoRA 的收益随 r 增大而下降：r 太大后，BA 参数与优化器状态也会重新变成显存瓶颈。

## 它和什么容易混淆

- **量化（QLoRA）**：LoRA 减少“可训练参数量”，QLoRA 进一步把冻结基座量化为 4-bit，降低基座权重本身的存储；
- **模型大小 vs 训练态显存**：模型参数定义权重文件大小；训练显存还取决于梯度、优化器状态和激活；
- **前向激活显存**：LoRA 不自动消除长上下文带来的激活显存，仍需梯度检查点、张量并行、序列并行等方法。

## 局限与实践建议

- r 与目标模块选择影响容量：不是所有任务都适合极小 r；
- 冻结基座可能导致灾难性遗忘较少，但可塑性也受限；
- 激活、通信和 kernel 工作区可能成为新瓶颈；
- 优化器实现、精度模式、checkpointing 策略会改变实际显存；
- 部署多适配器时，需权衡合并权重与动态路由的延迟。

## 为什么现在值得关注

LoRA 的显存机制解释了消费级 GPU 微调大模型的基础，也为理解 QLoRA、DoRA 等后续方法打下基础：冻结基座、训练低秩/轻量增量、再组合量化或并行策略。
