# 今日知识点：旋转位置编码：用复数旋转表示相对位置

> 一句话：它把 token 位置变成向量旋转，让注意力天然感知相对距离。

**分类**：基础原理　**难度**：4　**资料截至**：2026-09-20

## 它解决什么问题

Transformer 的自注意力本身不理解顺序：把“猫追狗”和“狗追猫”的 token 打乱后，注意力计算仍能进行，但语义会变。因此必须注入位置信息。绝对位置编码简单，但外推到更长序列时不稳定；相对位置编码表达距离，却常需要在注意力内部做额外偏置计算。RoPE（Rotary Position Embedding）的目标是把两者结合起来：像绝对编码一样直接作用在 query/key 向量上，同时让内积只依赖相对位置，便于建模词序和长距离依赖。

## 工作机制

RoPE 把每个 query/key 向量的相邻两维看成一个二维平面上的点，并根据 token 位置乘以不同角度的旋转矩阵：

- 位置 `m` 的 query 旋转 `mθ`；
- 位置 `n` 的 key 旋转 `nθ`；
- 两者做内积时，旋转角相减，只剩相对角度 `(m-n)θ`。

这来自复数乘法性质：复数模长相乘、辐角相加。因为注意力分数来自 query 与 key 的内积，最终分数只由内容和相对距离决定，而不是绝对下标。

直觉上，可以把每个 token 想成一个指针：位置越远，指针旋转越多。两个 token 计算相关性时，比较的是两个指针的夹角；夹角对应它们的相对距离。不同维度使用不同频率，低频维度捕捉长距离关系，高频维度区分邻近位置。

## 一个具体例子

假设两个词在序列中的距离始终是 3：

- 位置 2 和 5 比较，相对角是 `(5-2)θ = 3θ`；
- 位置 100 和 103 比较，相对角仍是 `(103-100)θ = 3θ`。

只要内容相同，它们在对应维度上的注意力几何关系一致。这个性质使 RoPE 在长文本、代码和多轮对话中较稳定。后来很多模型还基于这个几何形式做位置插值或频率调整，把训练长度扩展到更长上下文，但这些扩展方法不属于 2021 年 RoFormer 论文本身。

## 它和什么容易混淆

- **RoPE vs 正弦位置编码**：正弦编码把位置向量加到输入 embedding 上；RoPE 在每层注意力的 query/key 上做旋转。
- **RoPE vs 可学习绝对位置编码**：后者直接学习每个位置的向量，外推到未见位置较困难；RoPE 的内积依赖相对角度。
- **RoPE vs ALiBi**：ALiBi 在注意力分数上按距离加线性惩罚；RoPE 是旋转 query/key，让内容与相对位置在几何上相乘。

## 局限与实践建议

- **不是任意长度外推**：原始 RoPE 训练长度之外的频率仍可能表现异常，长上下文通常需要位置插值、频率缩放或继续训练。
- **维度配对方式影响实现**：相邻两维配对与前后半维配对在数学上等价，但代码兼容性不同。
- **“相对位置好”不等于任务好**：位置编码只提供顺序偏置，性能仍取决于数据、模型和训练目标。
- **长上下文评估要分层**：应在不同距离的信息检索和依赖追踪任务上测试，而不是只看困惑度。

## 为什么现在值得关注

现代大语言模型和多模态模型广泛使用旋转位置编码及其变体。理解“旋转角度相减”的机制，有助于读懂长上下文扩展、注意力缩放和模型配置中的 RoPE 参数。本文聚焦 RoFormer 原始机制，不引用未核实的当前模型实现细节。
