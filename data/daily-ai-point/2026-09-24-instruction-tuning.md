# 今日知识点：指令微调：把语言模型变成能听懂任务的助手

> 一句话：用大量“指令—回答”样本教模型按任务要求行动。

**分类**：训练与对齐　**难度**：3　**资料截至**：2026-09-24

## 它解决什么问题

预训练语言模型学会了续写文本，但不一定理解“请总结成三点”“只输出 JSON”“用中文解释，不要给答案”这类任务约束。零样本提示能缓解一部分问题，但模型常偏离格式、加入无关续写或忽略限制。指令微调把自然语言指令变成训练目标：给定任务描述和输入，训练模型输出符合要求的回答。目标是让模型在没见过的任务上也学会“听懂指令”。

## 工作机制

1. **构造指令数据集**。每条样本通常包括任务指令、可选上下文、输入和期望输出。任务覆盖问答、摘要、翻译、改写、分类、抽取、代码解释等。
2. **格式化为序列**。训练时把指令和输入拼接成 prompt，把目标输出作为标签，计算语言建模损失。
3. **多样化指令表达**。同一个任务可用不同措辞描述，促使模型学习任务语义，而不是记住特定模板。
4. **评估未见任务**。关键不是看训练集损失，而是在 held-out tasks 上做零样本或泛化测试。
5. **与人类反馈结合**。指令微调常是基础，再经过偏好优化或 RLHF 改进回答质量与安全。

FLAN 论文把一系列 NLP 数据集改写成指令模板并在多任务上微调；论文报告，在未见的任务族上，指令微调后的 137B LaMDA-PT 超过零样本 GPT-3 175B，说明任务表述形式的监督信号比单纯参数量更重要。

## 一个具体例子

普通预训练模型看到：

```
请把以下句子翻译成英文：今天天气很好。
```

可能继续写：“请把以下句子翻译成法文……”因为它是续写模式。

指令微调后的训练样本是：

- 指令：Translate the sentence to English.
- 输入：今天天气很好。
- 输出：The weather is nice today.

当模型见过大量类似但措辞不同的任务后，即使遇到新任务，如“把这段代码的复杂度解释给初学者”，也能把自然语言约束映射为执行目标。

## 它和什么容易混淆

- **指令微调 vs 少样本提示**：少样本提示不改参数，只在上下文里给示例；指令微调用数据更新模型。
- **指令微调 vs RLHF**：指令微调主要学习“按指令完成任务”，RLHF 或偏好优化进一步学习人类偏好、安全边界和回答风格。
- **指令微调 vs 领域微调**：领域微调常聚焦领域知识和语言分布，指令微调更强调任务表述与泛化。两者可以重叠。

## 局限与实践建议

- **数据质量决定行为**：模板错误、标注不一致、格式混乱都会被模型学走。
- **指令不等于可举一反三**：训练任务覆盖不足时，新任务格式仍可能失败。
- **过度拟合模板**：如果任务表述单一，模型会依赖特定措辞而不是任务语义。
- **评估要覆盖未见任务**：只在训练任务上测试会高估泛化能力。
- **安全与能力同步评估**：指令跟随能力提升也可能让模型更容易执行有害指令，需要配套安全训练和测试。

## 为什么现在值得关注

从聊天助手、Agent 工具调用到企业 API 的结构化输出，都依赖模型把自然语言约束转成行为。理解指令微调，有助于判断模型为什么不听话，以及该换提示、换数据还是重新微调。
